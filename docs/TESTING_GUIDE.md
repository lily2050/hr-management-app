# 🧪 دليل الاختبار

## اختبار API بـ Postman

### 1. تحضير البيئة

1. ثبت Postman
2. أنشئ Collection جديدة
3. أضف متغيرات:
   - `baseUrl`: http://localhost:5000
   - `token`: (سيُملأ بعد تسجيل الدخول)
   - `employeeId`: (معرّف موظف)

### 2. اختبار المصادقة

**POST** /api/auth/login
```json
{
  "email": "admin@company.com",
  "password": "Admin@123"
}
```

توقع الرد:
```json
{
  "success": true,
  "message": "تم تسجيل الدخول بنجاح",
  "data": {
    "user": { ... },
    "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."
  }
}
```

حفظ الـ token للطلبات التالية:
```
Headers -> Authorization -> Bearer {{token}}
```

### 3. اختبار الموظفين

**GET** /api/employees
```
Authorization: Bearer {{token}}
```

**POST** /api/employees
```json
{
  "userId": "...",
  "employeeCode": "EMP004",
  "department": "...",
  "position": "مهندس",
  "hireDate": "2026-01-01"
}
```

**PUT** /api/employees/{{employeeId}}
```json
{
  "position": "مهندس أول"
}
```

### 4. اختبار الإجازات

**POST** /api/leaves
```json
{
  "employee": "{{employeeId}}",
  "leaveType": "...",
  "startDate": "2026-09-15",
  "endDate": "2026-09-20",
  "reason": "إجازة شخصية"
}
```

**PUT** /api/leaves/{{leaveId}}/approve
```json
{
  "notes": "تمت الموافقة"
}
```

### 5. اختبار الأذونات

**POST** /api/permissions
```json
{
  "employee": "{{employeeId}}",
  "date": "2026-09-06",
  "outTime": "14:00",
  "returnTime": "15:00",
  "permissionType": "...",
  "reason": "موعد طبي"
}
```

## اختبار الواجهة (Frontend)

### تصفح جميع الشاشات

1. **شاشة تسجيل الدخول**
   - اختبر تسجيل صحيح
   - اختبر بيانات خاطئة
   - اختبر إظهار/إخفاء كلمة المرور

2. **الصفحة الرئيسية**
   - تحقق من الإحصائيات
   - تحقق من الطلبات المعلقة
   - تحقق من الملاحة

3. **إدارة الموظفين**
   - البحث والفلترة
   - عرض التفاصيل
   - تعديل البيانات

## سيناريوهات الاختبار

### السيناريو 1: طلب إجازة كامل

1. موظف يسجل الدخول
2. ينقر على "طلب إجازة"
3. يملأ البيانات
4. يقدم الطلب
5. مدير يراجع الطلب
6. مدير يعتمد/يرفض
7. موظف يرى الحالة

### السيناريو 2: تسجيل إذن

1. موظف يسجل الدخول
2. ينقر على "طلب إذن"
3. يملأ البيانات (الوقت)
4. يقدم الطلب
5. النظام يحسب المدة
6. مدير يعتمد الإذن
7. يتم تحديث الأذونات المستخدمة

### السيناريو 3: عرض التقارير

1. موظف إدارة يسجل الدخول
2. ينقر على "التقارير"
3. يختار نوع التقرير
4. يختار التاريخ
5. يشاهد النتائج
6. يصدر PDF أو Excel

## اختبارات الأمان

### 1. SQL Injection
```
GET /api/employees?name='; DROP TABLE employees; --
```
توقع: يرفض الطلب

### 2. XSS
```
name: <script>alert('xss')</script>
```
توقع: يتم تنظيف البيانات

### 3. CSRF
- اختبر بدون CSRF token
- توقع: رفض الطلب

### 4. Authentication Bypass
```
اختبر بدون token
اختبر مع token منتهية
اختبر مع token مزيفة
```
